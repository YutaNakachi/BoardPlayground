# 将来構想: 常設オンラインロビー

**ステータス: 未実装（メモのみ）**  
**記録日: 2026-09-22**

## やりたいこと

部屋を一度作ったら、明示的に退出するかブラウザを閉じるまで（閉じた後も再接続可能なら尚よし）、**同じメンバー同士で何度でもオンライン対戦を楽しめる**体験。

- 今の「1部屋 = 1ゲームの1対局」から、**常設ロビー + 対局セッション**へ拡張するイメージ
- ブラウザ（Web アプリ）だけで提供。ネイティブアプリは不要
- サーバー側（Supabase + API）に部屋状態の正本を持つ（P2P 単体は採用しない）

## 現状（2026-09 時点）

| 項目 | 現状 |
|------|------|
| 対応ゲーム | `reversi`, `tic-tac-toe`, `gomoku`, `checkers`（`lib/online/types.ts`） |
| 部屋の寿命 | 作成から **24時間**（`rooms.expires_at`） |
| ゲーム | 部屋作成時に **slug 固定** |
| 同期 | Supabase Realtime（`room_state`）+ ポーリング fallback |
| プレイヤー ID | `localStorage`（`bp_player_id`） |
| 退出 | 明示 API なし。DB 上は残る |
| 再接続 | 部屋 ID の永続化・復帰フローなし |
| 終了後 | `status: finished` になるが、再戦・ロビー復帰は未整備 |

関連コード: `hooks/useOnlineRoom.ts`, `app/api/rooms/`, `supabase/migrations/002_rooms.sql`

## 実現可能性

**ブラウザだけで十分可能。** 既存の Supabase Realtime + API Route の上に、ロビー層を足す形が自然。

```
[ブラウザ] ←→ Realtime / REST ←→ [rooms / members / sessions]
```

## 設計の要点

### 1. ロビーと対局を分ける（推奨）

```
Lobby（常設）
  ├ メンバー一覧（在席表示）
  └ GameSession（1局）→ 終了 → ロビーに戻る → 再戦 or 別ゲーム
```

- 部屋は `lobby`、各対局は `session` として切り替え
- 現状の `rooms.game_slug` 固定は、ロビー化時に見直しが必要

### 2. 再接続

- `localStorage` に `roomId` + `playerId` を保存
- 起動時に前の部屋へ復帰を試行（タブ更新・一時切断対策）
- `playerId` は既存の `getOrCreatePlayerId()` を流用可能

### 3. プレゼンス（在席）

- Realtime Presence または heartbeat で「今オンライン」を判定
- ブラウザを閉じたメンバーはオフライン表示（DB 行は残して再参加可能にするかは要決定）
- ゴーストメンバー対策として必須

### 4. 部屋ライフサイクル

- `expires_at` の自動延長（最終アクセスから N 時間）または明示退出で削除
- 全員退出・ホスト退出時のホスト移譲ルール
- 長時間放置部屋のクリーンアップ（cron / Supabase scheduled）

### 5. 終了後フロー

- 対局終了 → ロビーへ戻る
- ホストがゲーム選択 → 参加者同意（または 2人なら即開始）→ 新セッション
- 同一部屋コードで再戦・別ゲーム

### 6. ブラウザ制約（許容する挙動）

| 制約 | 対応方針 |
|------|----------|
| タブ閉じる | リアルタイム通知は止まる。復帰時に再接続 |
| モバイルスリープ | WebSocket 切断あり → 再接続 + 状態再取得 |
| 同時接続数 | Supabase Realtime の上限・料金を確認 |
| 不正手 | サーバー側で合法手検証（現 `move` API と同方向） |

## 実装フェーズ案（将来）

1. **再戦のみ** — 同一部屋・同一ゲームで `finished` → `waiting` → 再開始（最小変更）
2. **再接続** — `roomId` 永続化、リロード後の復帰 UI
3. **プレゼンス** — オンライン / オフライン表示、明示退出 API
4. **ロビー化** — ゲーム選択・複数セッション、部屋 TTL の見直し

## やらないこと（この構想では）

- WebRTC P2P 単体での同期
- 手札非公開ゲームのオンライン（CPU 対戦メモと同様、ロビー整備後に別検討）
- ユーザー登録・フレンドリスト（初期は部屋コード共有のまま）
