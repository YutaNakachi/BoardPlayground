# ココナラ — 購入〜着手の流れ

出品・返信の運用メモ。**掲載文案（サービス内容・購入のお願い・見積り・オプション価格）の正は [listing.md](./listing.md)**。見積点数は [complexity-checklist.md](./complexity-checklist.md)。

## 流れ

1. **見積り相談（必須）** … メッセージで内容確認。複雑度チェック表に基づく **暫定見積り**（変わる可能性を伝える）。
2. **初回購入** … **基本25,000円のみ**（複雑度オプションは付けない）。
3. **仕様すり合わせ** … メッセージ／ビデオチャットで確定。
4. **最終見積り** … 暫定との差分を明示。
5. **オプション追加購入** … トークルームから、確定に合う複雑度オプション（＋その他）を追加購入。
6. **着手** … 仕様確定 **かつ** オプション追加購入完了後。

## 見積が変わったとき

| 場合 | 対応 |
|------|------|
| 暫定より上がった | 該当オプションを追加購入してから着手 |
| 暫定と同じ帯 | 該当オプションを追加購入してから着手 |
| 暫定より下がった | **基本25,000円の範囲内で対応**（出品の購入のお願いに未記載なら取引で案内） |

## ココナラ上の注意

- 購入済みオプションの差し替えはできない。追加分は **有料オプションの追加購入** または **おひねり**（合意・購入者操作）。
- 複雑度帯オプションは **該当1つ** を選ぶ想定（同一オプションの複数購入は想定しない）。
- 追加決済ごとに購入者側手数料がかかる。

## 当方都合で実装・納品できない場合

- ヒアリング・仕様整理の工数があっても **全額返金の取引キャンセル**（当該取引で支払い済みの金額）。
- 整理したルールの仕様書など、その時点の副産物を無償提供（Web実装なし）。文案は [listing.md](./listing.md) の【実装可否】。
- 手続き: トークで説明 → 出品者からキャンセルリクエスト → 購入者の合意。
